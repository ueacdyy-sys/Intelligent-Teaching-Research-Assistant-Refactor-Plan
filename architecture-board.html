模块边界与禁止跨界

这页是给 AI 施工用的边界说明。每个模块只做自己该做的事，跨模块只能走 API、事件或端口接口，不能直接互相读库、互相 import、互相偷状态。

可复用 可替换 禁止串线

总规则

UI 调用 BFF，BFF 调用用例，用例调用端口，端口由数据、工具、AI Worker 实现。业务规则不能依赖具体框架、数据库、浏览器、Office、CLI。

复用方式

复用不是复制代码，而是沉到 Shared Kernel、契约 SDK、Domain Event、Tool Manifest。只有稳定、跨模块共用的东西才能下沉。

禁止方式

禁止前端直接拼后端地址，禁止 Agent 直接执行命令，禁止 AI Worker 写主库，禁止一个模块直接改另一个模块的表。

模块 包含 不包含 主语言 对外契约 AI 施工禁令
Identity 教师、学生、管理员、会话、角色、权限、设备登录态。 不写教学业务，不保存知识库正文。 Go + Rust Secure Store Auth API、Session DTO、Role Policy 不得把角色判断散落到 UI 组件里。
Workbench Shell 窗口、悬浮球、导航、主题、通知、审批面板、前端 SDK。 不写评分规则，不直接调用本机命令。 TypeScript + Rust/Tauri Frontend SDK、UI Events 不得在页面里硬编码后端地址和 mock 数据。
Teaching 测验、点名、批改、课堂白板、教学资料、教师课堂工具。 不管理模型节点，不执行外部应用操控。 Go Domain + TS UI Teaching API、teaching.* Events 不得直接读取科研私密知识库。
Student Profile 学生档案、成长资料、能力维度、个性化题库、学习反馈。 不保存教师私密科研资料，不直接训练模型。 Go + Python Analysis Profile API、profile.updated Event 不得让学生访问他人档案。
Research 多模型对话、节点管理、收藏、知识库、RAG、论文/资料工作流。 不直接操作系统命令，不绕过权限访问学生隐私。 Go + Python Worker Research API、research.* Events 不得把模型 API Key 放到前端或日志。
Knowledge Platform 公开库、私密库、目录索引、向量索引、文档解析、检索审计。 不决定教学流程，不决定 Agent 是否能执行命令。 Python RAG + Rust Indexer Knowledge Query Port、ingest events 不得混用公开库和私密库物理存储。

领域对象 核心字段概念 关系 存储建议 隐私/权限
Teacher / Student / Class id、displayName、role、classId、status、createdAt。 Teacher 管理 Class，Class 包含 Student。 PostgreSQL 学生只能读自己；教师只能读所管班级。
Quiz / Answer / GradingTask quizId、questionSet、answerSheet、score、rubric、reviewStatus。 Quiz 产生 Answer，Answer 进入 GradingTask，结果写 ProfileEvent。 PostgreSQL + Object Store 答题原件和批改证据按班级隔离。
StudentProfile / ProfileEvent studentId、abilityVector、trend、sourceType、evidenceId。 由测验、点名、批改、辅导、资料阅读事件聚合。 PostgreSQL + Analytics View 属于高敏数据，默认不进入科研知识库。
TeachingMaterial / ArchiveAsset assetId、ownerId、classId、fileHash、type、visibility、indexStatus。 白板、作业、导学案、试卷、教师资料统一归档。 Object Store + PostgreSQL Metadata 公开给班级前必须有发布状态。
Conversation / Message conversationId、role、content、nodeRuns、fusionTrace、citations。 Message 可被 Bookmark 引用，可生成 DatasetCandidate。 PostgreSQL 私密对话默认不进入公开知识库。
ModelNode nodeId、nodeType、endpoint、capabilities、health、knowledgeScope。 Conversation 调度 Node，Node 权限决定可读知识库范围。 PostgreSQL + Local Secure Store 云端只读公开库，本地可读授权私密库，远程设备不读本机私密库。
KnowledgeDocument / IndexChunk docId、visibility、structurePath、chunkId、embeddingRef、sourceHash。 Document 解析为目录索引和向量索引，检索结果必须带来源。 PostgreSQL + Qdrant/Chroma + Object Store 公开库和私密库物理隔离，查询记录可审计。
Bookmark / DatasetCandidate bookmarkId、messageId、tags、qualityScore、cleanStatus、datasetRef。 Bookmark 清洗后可成为训练数据候选。 PostgreSQL 进入训练前必须确认授权和脱敏状态。
Command / Plan / Approval commandId、intent、planSteps、riskLevel、approvalState、actorId。 外部入口和语音入口都先生成 Command，再由 Plan 执行。 PostgreSQL 高风险命令必须人工审批，不允许默认通过。
AgentTask / AgentRun / SharedContext taskId、leadAgentId、workerAgents、contextRef、budget、loopLimit、routeMode。 Command 生成 AgentTask；单 Agent 或 Swarm 都写入同一个 SharedContext。 PostgreSQL + Append-only Log 上下文按角色、知识范围、学生隐私和外部模型范围裁剪。
SkillManifest / SkillInvocation skillId、inputSchema、outputSchema、requiredPermissions、costHint、evidencePolicy。 Worker Agent 只能通过 SkillManifest 调用原子能力，调用结果进入 Evidence。 PostgreSQL + Object Store 无 manifest、无 schema、无权限声明的 Skill 不可执行。
MemoryEntry memoryId、scope、ownerId、retentionPolicy、sourceEvidence、redactionState。 短期记忆进入 SharedContext；长期记忆走 Memory Port，可选外部适配器。 PostgreSQL / Local Vault / Optional Adapter 学生隐私、私密知识库和外部模型上下文必须可撤销、可脱敏。
ToolRun / Evidence / Rollback toolRunId、toolName、inputsHash、outputsHash、screenshots、logs、rollbackRef。 每次工具执行都有证据，失败可定位，必要时可回滚。 PostgreSQL + Object Store 证据中必须脱敏密钥、路径、学生隐私。

API、命令与事件契约

重构时先写契约，再写实现。UI、Go API、Rust Harness、Python Worker 都按契约通信，避免弱模型时代那种“前端猜字段、后端临时返回”的混乱。

OpenAPI Domain Events WebSocket Command Gate

Query API

只读查询，例如列表、详情、搜索、状态。必须分页、可过滤、错误码稳定，不触发副作用。

Command API

会改变状态的请求，例如创建测验、发布资料、执行工具。必须返回 commandId 或 taskId，可追踪。

Event Stream

长任务、融合回答、训练、工作流执行通过事件流展示进度，UI 不轮询拼状态。

契约类型 示例 输入 输出 归属 验收规则
Auth API POST /api/v1/auth/login loginName、password 或扫码 token。 session、role、expiresAt。 Identity 错误码区分未认证、无权限、会话过期。
Teaching Command POST /api/v1/quizzes classId、questionSet、publishMode。 quizId、qrCodeUrl、status。 Teaching 创建后发 quiz.created 事件。
Student Command POST /api/v1/quizzes/{id}/answers studentId、answers、clientTime。 answerId、acceptedAt、gradingState。 Student 重复提交有幂等策略。
Profile Query GET /api/v1/students/{id}/profile studentId、viewScope。 profile、abilityTrend、evidenceRefs。 Student Profile 只返回当前角色允许看的字段。
Research Query POST /api/v1/research/query conversationId、prompt、nodePolicy、knowledgeScope。 streamId、selectedNodes。 Research 必须能看到融合进度和来源。
Node API POST /api/v1/model-nodes/{id}/health-check nodeId、checkMode。 health、latency、capabilities。 Model Node Registry 健康检查不泄露密钥。
Knowledge Ingest POST /api/v1/knowledge/documents fileRef、visibility、collectionId、indexStrategy。 docId、ingestJobId。 Knowledge Platform 公开/私密库必须显式选择。
Agent Command POST /api/v1/agent/commands text、source、riskConsent、attachments。 commandId、riskLevel、routeMode、approvalRequired。 Agent Orchestration 高风险命令先返回待审批；复杂任务标记单 Agent 或 Swarm。
Skill Invocation POST /api/v1/agent/skill-invocations skillId、input、contextRef、budget、approvalId。 invocationId、status、outputRef、evidenceRef。 Agent Orchestration + Harness 必须校验 manifest、schema、预算、权限和上下文范围。
Tool Run POST /api/v1/harness/tool-runs toolName、manifestId、arguments、approvalId。 toolRunId、status、evidenceRef。 Tool Adapter 无 manifest 或无审批必须拒绝。
Worker Job POST /api/v1/workers/jobs jobType、inputRefs、options。 jobId、queueState、resultContract。 Python AI Workers 结果只能通过 Job Result DTO 回到 Go。
WebSocket WS /api/v1/streams/{streamId} streamId、session token。 progress、delta、source、error、done。 Workbench 断线可重连，事件序号不乱。
Domain Event quiz.submitted / tool.run.completed eventId、type、actor、payload、occurredAt。 异步消费者处理。 Event Bus 事件必须可重放、可去重、可审计。

目标技术栈与语言分工

不要用一种语言解决所有问题，也不要为了换语言重写所有问题。Rust 负责本机可信边界，Go 负责真正拥有业务/任务/事件语义的平台服务，TypeScript 负责工作台体验，Python 作为 AI 工作者隔离保留。

前端：TypeScript 平台：Go 本机：Rust AI：Python 隔离

TypeScript UI

教师工作台、科研工作台、学生端、审批面板、数据可视化。迁移期可继续 React/Vite；真正减重靠 Tauri 替换 Electron、统一 SDK、减少散乱状态。

产物：Workbench UI Kit、Frontend SDK、Contract Client 代码来源：可用 Webcoding 生成，但必须本地规范化、类型化、测试化

Go Platform API

BFF、OpenAPI 合约、任务编排、事件处理、队列 worker、认证授权、业务子系统 API。适合长期维护和开源；不建议先做只转发 FastAPI 的空壳代理。

建议：net/http + chi 或 Fiber，SQLC/Ent，OpenAPI first 边界：拥有鉴权、聚合、限流、Job API、事件处理时才进入核心链路

Rust Local Runtime

桌面壳、本机文件索引、命令执行、CLI 适配、进程管理、权限沙箱、证据采集、Tauri 插件。

建议：Tauri、Tokio、Serde、SQLite、tantivy、reqwest 边界：所有本机能力都需要 permission manifest

Python AI Workers

RAG、OCR、文档解析、模型训练、语音、多模态、LLM 实验能力。保留 Python，但不再让 Python 承担总架构中心。

建议：FastAPI worker 或 gRPC worker，任务输入输出契约化 边界：无 UI、无直接系统命令、无散乱数据库写入

这页专门回答“当前系统有没有必要换语言”。空接口只能当参考，真正决策要看同库同表读写、连接预算、CPU 分布和可回滚迁移。

先拆写路径

完整 POST 与 Go 同表 insert 的差距约 5 倍。优先审计 FastAPI/Pydantic/SQLAlchemy/Redis dirty marker/响应 DTO 这条热路径，减少对象构造、重复提交、同步缓存写和事务持有时间。

目标：完整写入 P95 先降到 500ms 内 验收：write 800c 超过 2000 RPS，mixed 800c 超过 2500 RPS

Go 的真实收益

Go 的价值不是空接口快，而是能把高频写入、任务 API、事件消费者做成低开销、强契约、连接数可控的服务。它适合承接新的热切片或重写一个窄的 Command/Job 边界。

第一个 Go 切片：Conversation Write Gateway 或 Quiz Submit API 必须：OpenAPI、影子流量、双写校验、回滚路由、压测报告

配置是硬门槛

当前实际 PostgreSQL 是默认配置：max_connections=100、shared_buffers=128MB。24 worker 高压后会扩到 96 条 idle 连接，几乎没有余量给新服务。不上连接预算，Go 服务会把数据库顶满。

连接预算：workers × 每 worker 池数 + 新服务池数 <= max_connections × 70% 必须：PgBouncer 或提高 max_connections，并设置 idle_in_transaction_timeout
深度优化项 现象证据 处理方式 验收指标
连接池乘法 24 worker 高压后 PostgreSQL 看到 96 idle 连接。 统一 async/sync DB engine，或把 sync engine 改为 NullPool/PgBouncer transaction pooling。 压测后 idle 连接不超过连接预算，不能挤满 PostgreSQL。
写入热路径 同表 Go insert 5515 RPS，完整 FastAPI POST 1011 RPS。 减少 ORM/DTO 往返，短事务，必要时为高频写入建立 Go Gateway。 write 800c P95 小于 500ms，P99 小于 1000ms。
缓存一致性 写入后仍同步标记读缓存，Redis 在写压测时有可见 CPU。 保留版本 marker，但把非关键读缓存刷新事件化；严禁 wildcard scan。 写压测下 Redis 不成为 P95 主因。
PostgreSQL 配置 实际运行 shared_buffers 128MB，不是 perf compose 里的 1GB。 性能环境固定使用 perf compose 或显式 postgres command；开启 pg_stat_statements。 每次压测报告记录 max_connections、shared_buffers、连接状态、等待事件。
语言 保留/引入方式 学习收益 工程保护线
TypeScript 继续作为 UI 和前端 SDK 的主语言。 训练产品体验、状态管理、契约消费。 统一 API client，禁止散乱 fetch 和多处后端地址。
Python 保留 FastAPI legacy 和 AI/RAG/OCR worker。 训练 AI 工程、数据处理、模型生态。 AI worker 不直接写主业务库，不承担总线职责。
Go 从一个高频写入或任务事件切片进入，不包全站。 训练并发服务、契约服务、队列消费者。 必须在真实 DB/缓存/鉴权链路证明 P95 或吞吐改善，空接口不算。
Rust 从本机 Harness/Tauri/CLI sandbox 进入。 训练系统编程、权限边界、桌面 runtime。 不进入普通 CRUD；所有能力先有 Manifest 和审计。
深测后的判断：当前系统值得引入 Go，但不值得全量换语言；Go 应该先吃掉一个高频写入/任务事件边界，Rust 继续吃本机 Harness 边界。对 vibecoder 来说，多语言是经验加速器；对这个项目来说，多语言必须同时是风险隔离器和性能证据链。

Agent Harness 控制平面

这是新架构的保险丝。以后凡是“能控制电脑、能读写文件、能联网、能生成插件、能跑命令”的能力，都必须从这里过。

默认拒绝 审批放行 证据留存

Skills-Agent 两层

底层是可测试、可复用、可限权的原子 Skills；上层是 LeadAgent 和 Worker Agents。Agent 只负责计划、选择和汇总，真正影响文件、网络、系统和业务数据的动作必须交给 Harness 执行。

SwarmCoordinator

先判断走单 Agent 快速通道还是多 Agent 协作。只有跨教学、科研、知识库、工具或外部应用的复杂任务才进入 Swarm，并且必须写入 SharedContext 和预算。

Harness 执行链路

Command> LeadAgent> Swarm/Worker> Skill> Policy> Approval> Tool Adapter> Evidence> Rollback

业务模块只提交意图和参数，不能绕过 Harness 直接 shell、browser、office、file write。

权限清单 Manifest

每个 Skill、工具、插件、工作流都必须声明：输入输出 schema、读写范围、是否联网、是否打开外部应用、是否可回滚、需要什么角色、风险级别和预算。

证据与回滚

每次执行保存 request、参数 hash、命令预览、输出摘要、文件 diff、截图/日志、审批记录。可回滚的自动回滚，不可回滚的必须人工审批。

记忆与上下文

短期记忆只属于当前 AgentRun；长期记忆必须通过 Memory Port 写入。学生隐私、私密科研资料、外部模型上下文都必须可脱敏、可撤销、可解释来源。

工具适配与 CLI 优先原则

你说“对接 CLI 接口会好很多”，这个判断是正确的。新架构要把 CLI 适配器正式化，而不是把它当脚本临时跑。

API/SDK 第一 CLI 第二 浏览器第三 UI 兜底

1. API / SDK Adapter

最稳定。适合 OpenAI、模型服务、Notion、GitHub、数据库、云服务。输入输出可契约化，最适合 Agent 调用。

语言：Go client / TS SDK / Python client验证：OpenAPI contract + mock server

2. CLI Adapter

适合 Git、ffmpeg、office 转换器、模型工具、部署工具、浏览器下载器。需要命令白名单、参数 schema、输出解析。

语言：Rust process runner验证：固定参数、超时、exit code、stdout schema

3. File Protocol Adapter

适合 Word/Excel/PDF/图片/课程材料。通过文件读写、目录监听、版本备份实现半自动化。

语言：Rust file service + Python parser验证：hash、diff、备份、权限

4. Browser / UI Fallback

只在没有 API/SDK/CLI 时使用。它最脆弱，必须保存截图、选择器、域名、人工确认点。

语言：Browser automation验证：截图比对、下载校验、失败回退

数据、权限与事件架构

这里决定系统能不能长期维护。教学和科研可以打通，但必须通过事件和授权，不允许任意模块直接互相拿数据。

Shared Kernel Domain Events ACL

Shared Kernel

用户、组织、班级、课程、学生、角色、权限、文件资产、任务、通知、审计主体。这些是复用基础，不能散落在各模块自定义。

Domain Events

测验提交、批改完成、档案更新、收藏创建、知识库入库、模型节点失效、工作流发布都要变成事件。

Access Policy

从当前项目迁移到目标架构

不要让 AI 一次性重写 20 万行。正确做法是先设边界，再逐个垂直切片迁移。

不大爆破 按切片 可回滚
P0a
冻结与观测
原项目进入 Legacy Zone。导出 OpenAPI、数据库模型、功能清单、测试基线；固定 perf compose、记录 PostgreSQL 配置、连接状态、CPU、P95/P99，先把性能证据链补齐。
P0b
连接与写路径
统一连接预算，处理 async/sync engine 乘法；优化高频 POST 热路径。目标先让当前系统 write 800c P95 进入 500ms 内，再决定是否迁移该切片。
P1
合约先行
建立 OpenAPI 合约和 TypeScript SDK。前端不再散乱 fetch；Go 只承接拥有真实逻辑的新切片，不做单纯 FastAPI 转发壳。
P2
Go 热切片
选择 Conversation Write Gateway、Quiz Submit API 或 Job API 做第一个 Go 切片。必须具备影子流量、双写校验、回滚路由、压测报告。
P3
Harness 先落地
Rust Harness 接管命令、文件、Office、浏览器、CLI、插件、工作流执行。旧系统所有危险接口改为调用 Harness，不再直接执行。
P4
教学核心
迁移登录、班级、学生、测验、点名、批改、档案。每个功能一条竖切：UI + API + 数据 + 测试 + 事件。
P5
科研核心
迁移节点、对话、知识库、收藏、多模型融合。RAG 和训练继续放 Python worker，但输入输出契约化。
P6
Agent 产品化
先产品化 Skills-Agent 两层架构：LeadAgent、Worker Agents、SwarmCoordinator、SharedContext、Skill Manifest 和 Memory Port。工作流生成、插件生成、外部应用操控进入 Beta；默认关闭高风险能力，逐项通过权限、审批、测试、回滚和性能证据验收。
P7
开源版本
拆出 Community / Local / Pro 能力边界。开源核心保留教学、科研、知识库、基础 Agent；高风险远控、训练、平台集成以插件或企业能力处理。
优先迁移 登录、权限、测验、点名、学生档案、知识库、节点、对话、收藏。 收益高
延后迁移 模型训练、设备协同、数据可视化高级分析、工作流生成、Swarm 多智能体协作。 依赖多
谨慎开放 合规网络通道、全电脑操控、社交平台远程控制、插件自进化；不设计、不发布绕过网络监管的能力。 风险高

开源治理闸门

现在的项目不能直接开源。开源前要先过这张闸门，否则会把密钥、私有数据、危险能力、半成品接口一起暴露出去。

Blocker Must Fix Ready

开源前必须阻断

仓库历史中的 .env、证书私钥、固定口令、测试密钥必须清理并轮换。 危险能力默认关闭：命令执行、文件写入、Office 自动化、外部应用控制、远程控制。 测试不能依赖真实外网、真实第三方账号、真实浏览器状态。 README 不能宣称未完成能力已经生产可用。

开源版本能力边界

Community：教学/科研基础工作台、本地知识库、基础多模型对话、手动节点管理。 Local Advanced：Agent Harness、本机 CLI/API 适配、工作流池、插件池，但默认审批。 Pro/Private：社交平台接入、远程控制、训练集管理、多设备协同、企业审计。 所有版本都保留契约测试、权限声明、审计证据。

Harness Policy Test 模拟读写文件、命令、浏览器、外部应用。 默认拒绝危险操作，可审批，可审计，可回滚。 阻断 Agent 能力发布。
CI Quality Gate lint、typecheck、unit、contract、e2e、security、build。 主分支全绿，E2E 不依赖外网。 冻结合并，先修测试环境。

专业判断：这个项目开源的第一目标不是“功能震撼”，而是“边界可信”。只要边界可信，即使功能少一点，也会像一个认真项目；如果边界不可信，功能越多风险越大。
