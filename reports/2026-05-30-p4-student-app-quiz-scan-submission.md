# P4 Student App Quiz Scan Submission

## Slice

- SDD: `docs/sdd/0066-student-app-quiz-scan-submission.md`
- Root requirement anchor: Student App includes account login, AI tutor, student archive, teaching materials, personalized question bank, and scan-to-answer.
- Existing refactor evidence: SDD 0058 already records metadata-only scan submissions, and SDD 0064 lets the Student App list its own submitted answer metadata.

## Contract

- Added `POST /v1/student-app/quiz-scan-submissions`.
- Requires Agent API key plus Principal Context.
- Preserves SDD 0058 Student App authorization: `STUDENT_OWN_WRITE`, own-student access, and Student App entry point.
- Accepts `scanCode` and `answerRef`.
- Reuses `CreateScannedQuizSubmission`, so `studentId` is forced from Principal Context rather than request JSON.
- Keeps the existing `POST /v1/teaching/quiz-scan-submissions` route available.

## Design Notes

- This is a mobile namespace contract over an existing use case, not a second scan-answer business path.
- The QR payload remains a bounded locator, not a security boundary.
- The authenticated student's identity remains Principal Context owned.
- No SQL table, package manifest, OCR/RAG/model, scoring, or training dependency was added.
