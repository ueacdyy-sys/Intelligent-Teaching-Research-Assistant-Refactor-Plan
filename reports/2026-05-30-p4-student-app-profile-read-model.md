# P4 Student App Profile Read Model

## Slice

- SDD: `docs/sdd/0067-student-app-profile-read-model.md`
- Root requirement anchor: Student App includes account login, AI tutor, student archive, teaching materials, personalized question bank, and scan-to-answer.
- Existing refactor evidence: Student App Teaching Archive routes now require own-student Principal Context, but the Identity gateway previously projected `OWN` access without a concrete own `studentId`.

## Contract

- Added `GET /v1/student-app/profile`.
- Requires a bearer access token.
- Returns a mobile-facing profile read model: `studentId`, `principalId`, `displayName`, `role`, `entryPoint`, `sessionId`, `issuedAt`, and `expiresAt`.
- Rejects non-Student App or non-student principals with `403`.
- Keeps internal `scopes` and `knowledgeAccess` out of the profile response.
- Projects Student App password sessions with `studentAccess.studentIds=[account.ID]`.

## Design Notes

- This is a Student App read model, not a replacement for the full `PrincipalContext` authorization boundary.
- The response intentionally avoids leaking scopes or private knowledge access policy.
- The own student id is now present in student sessions, which makes downstream own-student Teaching Archive gates usable with real Identity tokens.
- No SQL table, package manifest, OAuth provider, OCR/RAG/model, or training dependency was added.
